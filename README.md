# 卖家利润助手 Web MVP

可以整合多平台的收益，给予直观的反馈。

本目录是一套可在本机运行的单用户经营数据分析 MVP。它支持店铺档案、Excel/CSV 上传、字段映射、逐行校验、SKU 成本版本、销售/退款/费用估算、对账异常、Excel 报告导出，以及 `/guide` 快速上手教程。顶部“对账异常”导航会显示待处理和待复核数量。应用不连接平台账号、不自动抓单、不把上传文件发到外部服务。

公开 Demo 的 Render 部署配置、临时数据保留规则、GitHub 推送步骤和风险清单见 [DEPLOYMENT_GUIDE.md](DEPLOYMENT_GUIDE.md)。公开部署尚未执行；不要把本机 SQLite、环境密钥或用户数据提交到 GitHub。

界面采用轻量导航、充足留白、克制配色和明确的标题层级，参考 Apple 官网的简洁视觉节奏；不使用 Apple 标识或其专有素材。

> 本产品输出的是“基于已导入数据的经营利润估算”，不是会计记账、税务申报或平台官方结算结论。成本或费用数据不完整时会显示缺项，未知金额不会被描述为完整利润。

## 数据库、备份与恢复

- 默认数据库：`data/seller_profit.sqlite3`。
- 可在启动前设置 `SELLER_MVP_DATA_DIR` 改变整套本地数据目录，或用 `SELLER_MVP_DATABASE` 指定数据库文件路径。
- 初始化：`.\.venv\Scripts\python.exe manage.py init-db`
- 备份：`.\.venv\Scripts\python.exe manage.py backup-db`。备份写入 `data/backups/`。
- 恢复：`.\.venv\Scripts\python.exe manage.py restore-db --backup seller_profit_时间戳.sqlite3 --confirm`。恢复前会自动备份当前数据库。
- 重置：`.\.venv\Scripts\python.exe manage.py reset-db --confirm`。重置前会自动备份当前数据库，再初始化空库。
- 载入演示：`.\.venv\Scripts\python.exe manage.py load-demo`。演示店铺和全部数据均为虚构；再次运行会跳过已加载的相同文件。
- 不要在服务运行期间手动删除 SQLite 数据库、WAL 或 SHM 文件。

## Excel/CSV 导入

- 接受 `.xlsx`、`.csv`、`.tsv`；不接受旧版 `.xls`。Excel 工作簿可选择工作表。
- 单文件不超过 20 MB、单表不超过 50,000 行；CSV 尝试 UTF-8/BOM 与 GB18030。
- 映射列后只保存被映射字段的原始值及标准化记录，不保存未映射列。订单号、SKU、数量、金额/单价、日期和状态按报表类型校验。
- 字段建议仅是列名匹配，确认之前要检查平台字段的真实含义。源文件本身会在本机暂存，导入完成/取消后删除；未完成暂存会在访问导入页时清理 24 小时前的文件。
- 同一店铺、报表类型、文件指纹重复上传会阻止再次累计；记录级相同业务键相同内容会跳过；相同业务键但内容不同会标记冲突，需人工核查。系统不会静默用新行覆盖旧订单。
- 行级记录含来源批次、工作表和源行号，可用于复核。

## 计算口径与默认规则

金额以整数分保存，乘数量时使用 Decimal 后按分四舍五入。商品成本按店铺 + SKU + 成本有效期匹配；缺成本 SKU 会列异常。新增成本版本时保留旧成本金额和版本，并收窄前一版本的有效期。

统计期间按事件日期分别过滤：订单按下单日、退款按退款完成日、平台费用/其他经营费用按发生日、结算按结算日。跨月退款会进入退款完成所在期间；取消/关闭订单不计销售；待付款或无法识别的订单状态不计销售并列异常；未确认退款/结算不进入已确认汇总。退款默认不冲回商品成本。

已知项目利润估算 = 商品销售额 − 本期间已确认退款 − 已匹配商品成本 − 已导入平台费用 − 已导入其他经营费用。该值仅代表已导入的范围；缺少成本、费用或报表时明确标注为不完整，不把未知金额解释成零或完整净利润。店铺级费用不强行分摊到商品；订单级费用和能匹配的订单级退款按商品销售额比例分摊到 SKU。商品分析的未分配金额会单独列出。

订单级结算对照仅对单个关联订单、已有订单行、已匹配费用和一条已确认结算记录作简化计算，并且只纳入该结算日之前发生的销售、退款和费用。这个差异是复核线索，不等于平台账单认定；多笔/汇总结算、不关联订单的资金变动不会被强行配对。

## 平台模板验证状态

淘宝/天猫、拼多多、抖音电商目前都走通用字段映射。随附 `data/demo_reports/` 的 CSV 是虚构的标准字段样本，不是三个平台的真实官方导出报表。当前没有提供这些平台的脱敏真实订单、退款、费用和结算样本，因此**平台官方格式、字段语义和结算口径均未验证，也不能称已兼容**。拿到样本后，需要逐种报表检查列名、金额字段含义、状态枚举、退款/结算跨期和重复业务键，再建立并测试平台模板。

## 当前功能清单

### 已实现

- 本地店铺档案、归档与筛选。
- XLSX/CSV/TSV 上传，工作表选择、通用字段自动建议及手工映射。
- 文件/记录去重、行级校验、来源记录与导入批次。
- 商品成本手工维护和成本表导入，按 SKU 与生效日留版本。
- 订单、退款、平台费用、结算、其他经营费用导入和本地 SQLite 持久化。
- 看板筛选、销售/退款/成本/费用/利润估算、趋势、商品与店铺分析。
- 缺失成本、状态异常、无法匹配记录和简化结算差异清单；支持备注和处理状态。
- 多工作表 Excel 报告导出、公式注入防护、数据库备份/恢复/重置工具。
- 虚构的边界案例演示报表和人工计算答案。

### 未完成或尚未验证

- 三个平台真实官方报表模板与状态/结算语义：**未验证**，需要实际脱敏样本。
- 多用户登录与隔离、云端部署、HTTPS、平台 API 授权和自动同步：不在本地首版范围。
- 正式会计/税务核算、订单修改、OMS/库存/采购/物流：不支持。
- 汇总平台账单、保证金/补贴/调整款、多笔拆分结算的自动匹配：目前只给有限的订单级简化对照。
- 店铺级广告/费用自动分摊到商品：不做自动分摊；保留为未分配金额。
- 跨币种：不支持，固定人民币。
- 同一业务键内容变化的自动更新：不做自动覆盖，会要求人工复核。

## 隐私与本地限制

服务默认仅监听 `127.0.0.1`。没有认证，也不适合直接共享到局域网或公网。上传解析不执行 Excel 公式；导出为静态值并对用户文本做公式注入处理。应用不调用 AI、外部 CDN 或平台 API。SQLite 数据和手工备份由使用者保管；请勿将含订单个人信息的原始文件发给他人测试。
